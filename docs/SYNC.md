# Optional Supabase sync

The local app requires no account. Sync is opt-in from Settings and requires your own Supabase project. Apply `supabase/migrations/001_sync.sql` in the SQL editor, enable email/password authentication and create a user. Configure the project URL and public anon/publishable key in Settings. Never use a service-role key. Passwords are not persisted. The access session is kept in sessionStorage for this tab only; signing out removes it.

Protocol: private rows keyed by authenticated user, table and record ID. Server versions plus compare-and-swap RPC prevent blind overwrites. Each device stores acknowledged versions and fingerprints in local IndexedDB settings. On sync, remote rows are fetched and conflicts resolved without discarding unacknowledged local changes; local differences are then queued durably and uploaded. Notes preserve both versions on conflict. Review events are immutable unique IDs; cards are rebuilt from merged logs. Other mutable records use their updatedAt timestamp. A retry follows a server version conflict; unacknowledged local changes stay queued.

Documents, chapters and raw reading files are deliberately excluded: cloud document storage and its separate consent/download flow are not implemented. Reading positions sync, but become useful only when the same document identity exists locally (e.g. restored from backup). Bulk public dictionary resources and built-in wordbooks are not uploaded; words referenced by personal wordbooks are included. Wordbook membership IDs, notes, vocabulary status, review events, vocabulary tests, reading positions, learning and reading preferences and personal dictionary additions are included. Session credentials and sync metadata are never included. Signing in explicitly enables sync of existing local learning records and binds this browser profile to that account. Switching to another account is refused; use a separate browser profile.

Startup/foreground/online trigger sync only with an active tab session. Mobile background execution is not guaranteed. Error status remains visible and manual retry is always available. No live cloud verification has been performed without project configuration. Automated tests cover provider-independent conflict resolution and excluded private-resource tables; deployment requires two-device validation of RLS, network interruption and simultaneous note edits.

Accent and dark-mode preferences currently remain device-local. Full document file sync, remote deletion of records without tombstones, and multi-account switching in one browser profile are not implemented. Use note clearing and journal tombstones for synchronized deletion; do not manipulate the database directly.
